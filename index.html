Introduzione al Blue Team

Il Blue Team difende, investiga e ricostruisce. In una CTF significa analizzare artefatti, trovare flag nascoste nei log, nei dump, nei PCAP, nelle immagini disco.

Framework di riferimento

  • NIST SP 800-61: ciclo IR in 4 fasi: Preparation, Detection & Analysis, Containment/Eradication/Recovery, Post-Incident Activity
  • MITRE ATT&CK: tassonomia di tecniche attacco per mappare cosa cercare
  • Pyramid of Pain: hash < IP < dominio < artefatti < tool < TTP
  • Diamond Model: Adversary, Capability, Infrastructure, Victim

Ordine di volatilità (RFC 3227)

  1. Registri CPU, cache
  2. Memoria RAM
  3. Stato rete (connessioni attive)
  4. Processi attivi
  5. File system, file cancellati
  6. Log remoti
  7. Configurazione sistema
  8. Archivi

Ordine operativo in CTF

  1. Leggi la traccia: cosa ti danno? (PCAP, dump, log, disk image)
  2. Identifica la fonte primaria e inizia da lì
  3. Usa Statistics/Overview prima di entrare nei dettagli
  4. Documenta ogni comando e output
  5. Correla fonti diverse per ricostruire la timeline

3.1 Network Forensics

Il PCAP è la fonte di verità: registra tutto ciò che è transitato in rete.

Anatomia di un pacchetto

  • L2 Ethernet: MAC sorgente/destinazione, EtherType
  • L3 IP: IP sorgente/destinazione, TTL, Protocol (TCP=6, UDP=17, ICMP=1)
  • L4 TCP/UDP: porte, flag (SYN, ACK, FIN, RST), sequence number
  • L7 Application: HTTP, DNS, TLS, SMB, Kerberos, LDAP

Wireshark - Primo approccio

  1. Statistics > Capture File Properties: durata, pacchetti, volume
  2. Statistics > Protocol Hierarchy: gerarchia protocolli
  3. Statistics > Conversations: coppie IP/porta con volume
  4. Statistics > Endpoints: host più attivi

HTTP - cosa cercare

  • User-Agent inusuale (curl, python-requests su traffico utente)
  • Authorization: Basic - credenziali in Base64 decodificabili
  • POST con payload binari o base64 grandi
  • Cookie di sessione
  • Referer per percorso navigazione
# Decodifica Basic Auth
echo "dXR1bnR10nBhc3N3b3Jk" | base64 -d

# Export oggetti HTTP
# Wireshark: File > Export Objects > HTTP

DNS - la porta d'ingresso

  • Query verso domini sospetti
  • Volume anomalo verso singolo dominio (DNS tunneling)
  • Sottodomini ad alta entropia (DGA)
  • Query TXT verso destinazioni inusuali
  • NXDOMAIN massivi
dns.qry.name contains "malware"
dns.qry.type == 16
dns.flags.rcode == 3

TLS - metadata non cifrati

  • SNI (Server Name Indication): dominio richiesto in chiaro
  • Certificato server: CN, SAN, CA, date
  • Cipher suite negoziata
  • JA3/JA4: fingerprint client TLS
tls.handshake.extensions_server_name
tls.handshake.type == 1

Kerberos - attacchi rilevabili

  • AS-REP Roasting: AS-REP con pre-auth disabilitata
  • Kerberoasting: TGS-REQ per SPN, risposta RC4 (0x17)
  • Golden/Silver Ticket: ticket forgiati
kerberos.msg_type == 10  # AS-REQ
kerberos.msg_type == 12  # TGS-REQ
kerberos.CNameString contains "admin"

Pattern C2

  • Beaconing: connessioni regolari a intervalli costanti
  • Domain fronting: C2 dietro CDN legittimo
  • DGA: domini generati algoritmicamente, molti NXDOMAIN

Detection di tecniche comuni

Password spraying (T1110.003)

  • Cluster di eventi 4625 con TargetUserName diversi
  • Status/SubStatus consistenti
  • Stesso IpAddress o pattern temporale stretto

Kerberoasting (T1558.003)

  • Eventi 4769 con TicketEncryptionType = 0x17 (RC4)
  • In ambienti AES-only, RC4 è IoC quasi perfetto
  • Query: index=windows EventCode=4769 TicketEncryptionType=0x17 | stats count by TargetUserName, ServiceName, src_ip

Pass-the-Hash / Pass-the-Ticket (T1550)

  • Eventi 4624 con Logon Type 3 da host insoliti
  • AuthenticationPackageName NTLM in ambienti Kerberos-only
  • Orari fuori norma dell'account

Lateral movement via PsExec/SMB (T1021.002)

  • Host sorgente: 4648 (logon explicit credentials)
  • Host destinazione: 7045 (service installed) con ServiceName casuale
  • Host destinazione: 4624 Logon Type 3 dal sorgente

PowerShell offuscato (T1059.001)

  • Eventi 4104 con contenuto che include -enc, -encodedCommand
  • Blob Base64 lunghi nel command line
  • Sysmon event 1 con CommandLine sospetto

Log clearing (T1070.001)

  • Evento 1102 nel canale Security
  • Allarme critico se non autorizzato

  1. Preparation: playbook, tool, baseline, esercitazioni
  2. Detection & Analysis: validare, classificare, correlare, identificare perimetro

3.4 Disk Forensics & File Carving

Il disco conserva memoria lunga: file, artefatti, attività utente, file cancellati recuperabili.

NTFS essentials

$MFT (Master File Table)

  • Entry per ogni file/cartella
  • $STANDARD_INFORMATION: timestamp MACB (Modified, Accessed, Changed, Born)
  • $FILE_NAME: altro set timestamp, nome file
  • $DATA: dati residenti o non residenti

Timestomping: attaccante modifica $STANDARD_INFORMATION ma dimentica $FILE_NAME → discrepanza IoC.

$LogFile e $UsnJrnl:$J

  • $LogFile: journal transazionale NTFS
  • $UsnJrnl:$J: journal di modifiche file (creazione, modifica, rinomina, cancellazione)

Alternate Data Streams (ADS)

# Sintassi: nomefile.txt:streamnascosto
# Rilevamento PowerShell
Get-Item C:\cartella\file.txt -Stream *

# Zone.Identifier: annota URL di origine file scaricati

Artefatti di esecuzione

Prefetch

  • File .pf in C:\Windows\Prefetch\
  • Nome binario, run count, ultime 8 esecuzioni, file/DLL usati
  • Parser: PECmd
PECmd.exe -d C:\Windows\Prefetch\ --csv C:\Output\ --csvf prefetch.csv

ShimCache / AppCompatCache

  • In hive SYSTEM: HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache
  • Persistente, sopravvive a cancellazione binario
  • Parser: AppCompatCacheParser
AppCompatCacheParser.exe -f C:\Evidence\SYSTEM --csv C:\Output\ --csvf shimcache.csv

AmCache

  • File C:\Windows\AppCompat\Programs\Amcache.hve
  • Path binario, hash SHA-1, prima esecuzione, publisher, versione
  • Parser: AmcacheParser
AmcacheParser.exe -f C:\Windows\AppCompat\Programs\Amcache.hve --csv C:\Output\ --csvf amcache.csv

Correlazione dei tre

Binario in Prefetch + ShimCache + AmCache = esecuzione documentata a 3 fonti.

Artefatti di attività utente

ShellBags

  • Entry registro di cartelle visitate in Explorer
  • In NTUSER.DAT: HKCU\Software\Microsoft\Windows\Shell\BagMRU
  • Persistono dopo cancellazione cartella o USB scollegato
  • Parser: SBECmd, ShellBagsExplorer

JumpList

  • Liste file recenti per applicazione
  • In C:\Users\<user>\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations\
  • Parser: JLECmd

LNK files

  • Shortcut .lnk con path target, timestamp, volume serial number
  • In C:\Users\<user>\AppData\Roaming\Microsoft\Windows\Recent\
  • Parser: LECmd

Recycle Bin

  • File in C:\$Recycle.Bin\<SID>\
  • $I<codice>: metadata (path originale, timestamp cancellazione)
  • $R<codice>: contenuto file originale
  • Parser: RBCmd

SRUM e Windows Timeline

SRUM

  • C:\Windows\System32\sru\SRUDB.dat
  • Bytes inviati/ricevuti per applicazione, CPU time, disco
  • Parser: SrumECmd

Windows Timeline

  • C:\Users\<user>\AppData\Local\ConnectedDevicesPlatform\L.<user>\ActivitiesCache.db
  • App aperte, file creati/modificati, pagine visitate
  • Parser: WxTCmd

3.5 Malware Analysis

Regola 1: sample live SOLO in VM isolata, senza connessione a Internet reale. Mai su host. Mai con cartelle condivise.

Laboratorio

  • FlareVM: Windows per analisi malware (Mandiant)
  • REMnux: Linux per analisi (Zeltser)
  • INetSim / FakeNet-NG: emulatori servizi rete
  • Rete host-only o internal network, mai bridged/NAT verso Internet
  • Snapshot pulito obbligatorio

Domande a cui rispondere

  1. Cosa fa il binario?
  2. Come si propaga e persiste?
  3. Con chi parla?
  4. Cosa esfiltra?
  5. Da dove viene?
  6. Come si difende dal rilevamento?

Output operativi

  • IoC: hash, IP, domini, mutex, percorsi
  • Regole detection: YARA, Sigma, Snort/Suricata
  • TTP mappate ad ATT&CK

Static analysis - leggere senza eseguire

Formato PE (Windows)

  • Header MZ, header NT, sezioni (.text, .data, .rsrc, .rdata)
  • Entropia: >7.5 = packed/cifrato
  • Nomi sezioni: .upx0, .aspack, .themida = packer
  • Import minimi: LoadLibrary + GetProcAddress = packer
  • Risorse anomale: payload secondario
  • Timestamp compilazione strano

Tool static

  • PEstudio: triage PE con IoC evidenziati
  • Detect It Easy (DIE): packer, compilatore, entropia
  • CFF Explorer: editor PE completo
  • PE-bear: analisi e diffing PE
  • capa: mappa capability ad ATT&CK
  • FLOSS: stringhe normali e offuscate
  • YARA: pattern matching
# Hash
sha256sum sample.exe

# Detect It Easy
die sample.exe

# capa
capa sample.exe

# FLOSS
floss sample.exe > strings.txt

# YARA
yara -r signature-base/yara/ sample.exe

Dynamic analysis - osservare in azione

Tool

  • Process Monitor (Procmon): filesystem, registry, processi, rete
  • System Informer: vista live processi, thread, handle, moduli
  • Autoruns: snapshot persistenza
  • TCPView: connessioni TCP/UDP
  • Wireshark: cattura traffico
  • Noriben: wrapper Procmon con report

  • Registra esecuzione di un processo come un nastro riavvolgibile
  • File .run di 50-500 MB
  • Comandi: g- (go backward), p- (step backward), !tt (time travel)
  • Ideale per: process hollowing, unpacking, anti-analisi

Anti-analisi

Anti-debug

  • IsDebuggerPresent()
  • CheckRemoteDebuggerPresent()
  • Lettura PEB.BeingDebugged
  • NtQueryInformationProcess(ProcessDebugPort)
  • Timing con RDTSC
  • Exception-based

Anti-VM

  • CPUID hypervisor bit (bit 31 di ECX dopo CPUID EAX=1)
  • Stringhe vendor CPU: "VMwareVMware", "VBoxVBox"
  • Driver VM: VBoxGuest.sys, vmmouse.sys
  • Processi VM tools: VBoxTray.exe, VMwareTray.exe
  • MAC address: 00:05:69 (VMware), 08:00:27 (VirtualBox)
  • Chiavi registro: HKLM\HARDWARE\ACPI\DSDT\VBOX__

Anti-analisi ambientale

  • Numero file recenti in Recent
  • Uptime sistema
  • Cronologia browser, dimensione Desktop
  • Movimento mouse, digitazione

Packing

  • UPX: unpack con upx -d
  • ASPack, ASProtect: commerciali, anti-debug
  • Themida, VMProtect: professionali, virtualizzazione codice
  • MPRESS, PECompact: leggeri
  • Custom: entropia >7, IAT minimal, stringhe assenti

Offuscamento stringhe

  • Stack strings (FLOSS le estrae)
  • XOR/RC4 con chiave hardcoded
  • Stringhe in risorse (.rsrc)
  • Stringhe fetched da remoto
